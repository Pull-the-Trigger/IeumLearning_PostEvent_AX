# 감사 메일 (backend/thanks_mail)

담당: 나혜 · 행사마다 참석자 전원에게 보낼 감사 메일 초안을 만듭니다.

## 하는 일

행사마다 참석자 전원에게 보낼 감사 메일 초안을 만듭니다. 메일에는 발표 자료 링크와 만족도 설문 요청이 들어갑니다.
**모든 메일은 초안(`status`=`draft`)입니다.** 본부장이 확인하기 전에는 보내지 않습니다(06 글쓰기 기준 4).

## 입력·출력

- 입력: `data/processed/profiles.json`, `events.csv`, `surveys.csv`
- 출력: `out/thanks_mails.csv` (UTF-8 BOM이라 엑셀에서 바로 열림). `out/`에는 참석자 정보가 들어 있어 GitHub에 올리지 않습니다(`.gitignore`).
- 실행이 끝나면 행사별 통수, 설문 요청을 뺀 수("설문 뺌"), 글쓰기 기준 경고를 출력합니다.

### 출력 열 (`out/thanks_mails.csv`)

소민 님 맞춤 메일 CSV(`out/custom_mails.csv`)와 앞쪽 7개 열(`event_id`, `event_name`, `email`, `name`, `company`, `title`, `consent`)이 같습니다.

| 열 | 뜻 |
|---|---|
| `event_id`, `event_name` | 행사 ID, 행사명 (events.csv) |
| `email`, `name`, `company`, `title`, `consent` | 받는 사람 (profiles.json) |
| `mail_type` | `thanks` |
| `survey_included` | 설문 요청 문단이 들어가면 `Y`, 현장 QR 응답자라서 요청을 빼고 응답 감사 문단을 넣었으면 `N` |
| `sender` | 보내는 사람 (config.json `sender`) |
| `send_by` | 발송 기한 `YYYY-MM-DD HH:MM` (행사일 + `send_by_days_after`, `send_by_time`) |
| `status` | `draft` (본부장 확인 전) |
| `subject`, `body` | 제목, 본문 |

### 설정 파일

#### `backend/thanks_mail/config.json`
```json
{
  "sender": "이음러닝 마케팅본부장 한서윤 <sy.han@ieumlearning.example>",  // 보내는 사람 (비어 있으면 멈춤)
  "send_by_days_after": 1,       // 발송 기한: 행사일 며칠 뒤까지
  "send_by_time": "12:00",       // 발송 기한 시각 (HH:MM)
  "exclude_events": ["E07"],     // 감사 메일을 만들지 않을 행사
  "links": {"E04": {"slides": "...", "survey": "..."}}   // 행사별 발표 자료, 설문 링크
}
```
- 참석자가 있는 행사의 링크가 없으면 멈춥니다(종료 코드 1). 새 행사를 열면 `links`에 먼저 추가해 주세요.
- 링크에 이메일 같은 개인정보를 넣지 않습니다. 링크에 `@`가 있으면 멈춥니다. 설문 링크는 전원에게 같은 링크 하나를 보냅니다.

#### `backend/thanks_mail/template.txt`
코드를 고치지 않고 이 파일만 고치면 모든 행사의 기본 문안이 바뀝니다. 한 행사만 고칠 때는 화면에서 고칩니다(아래 "화면에서 문안·링크 고치기").
- 첫 줄 `제목: …`이 제목이고, 그 아래가 본문입니다.
- 치환 자리: `{이름} {직함}님`(직함이 없으면 통째로 `담당자님`이 됩니다), `{행사명}`, `{M월 D일}`, `{발표 자료 링크}`, `{설문 링크}`, `{서명}`
- 본문은 `{서명}`으로 끝나야 합니다(그 뒤에는 설문 문단 두 개만). 서명은 `signature.txt`로 고정이고, `{서명}` 앞까지가 본문 문안입니다.
- 본문의 `{설문 문단}` 자리에는 파일 아래쪽에 있는 두 문단 가운데 하나가 들어갑니다.
  - `{설문 요청}` … `{설문 요청 끝}`: 설문 요청을 받는 사람(`survey_included`=`Y`)
  - `{설문 응답 감사}` … `{설문 응답 감사 끝}`: 현장에서 이메일을 적고 응답한 사람(`survey_included`=`N`)
  - 두 문단 가운데 하나라도 없으면 멈춥니다(종료 코드 1).

#### `backend/thanks_mail/signature.txt`
메일 끝의 `{서명}` 자리에 들어갑니다(구분선부터 연락처까지).

## 규칙과 근거

| 규칙 | 근거 |
|---|---|
| 대상은 각 행사의 참석자(`attended`=`Y`) 전원입니다. 한 사람이 여러 행사에 참석했으면 행사마다 한 통씩 보냅니다. 테스트 행사(E07)는 뺍니다. | 인터뷰 7번 |
| 수신 동의와 상관없이 보냅니다. 감사 인사, 발표 자료, 만족도 설문은 미동의자에게도 보내도 되는 "행사 운영에 필요한 안내"입니다. | 인터뷰 5번, 06 글쓰기 기준 4 |
| 발송 기한(`send_by`) 기본값은 행사 다음 날 12:00입니다. | 인터뷰 7번 ("행사 다음 날 오전에 한 번") |
| 같은 행사 설문에 이메일을 적고 행사 당일 응답한 사람(현장 QR 응답)에게는 설문 요청을 빼고, 대신 응답에 감사하는 문단을 넣습니다. | 인터뷰 7번 |
| 이메일 없이 응답한 사람은 누구인지 알 수 없으므로 설문 요청 문단을 넣습니다. 이 문단에는 인터뷰 7번이 정한 문장 "이미 응답하셨다면 넘어가셔도 됩니다."를 그대로 둡니다. 참석 명단과 짐작으로 연결하지 않습니다. | 인터뷰 4·7번 |
| 감사 메일은 행사 당일 밤에 만든다고 보고, 행사 다음 날 이후의 응답은 반영하지 않습니다. 다음 날 이후에 응답한 사람도 설문 요청 문단을 받습니다. | 발송 시점 기준 |
| 발신자는 마케팅본부장 한서윤 명의입니다. 대표 계정은 단체 메일로 읽힐 수 있기 때문입니다. | 인터뷰 9번 |
| 감사 메일은 전원에게 같은 문안이 나가므로, 본부장은 문안을 한 번만 확인하면 됩니다. | 인터뷰 8번 |
| **질문 답변은 감사 메일이 아니라 맞춤 메일(72시간 안)에서 합니다.** 감사 메일에는 사전 질문이나 관심 글을 넣지 않습니다. | 인터뷰 7·8번 |
| 산업군(industry) 필드는 쓰지 않습니다. 행사명과 날짜는 events.csv에서 가져옵니다. | data-schema.md (industry는 내부용) |

- `send_by`: 행사 다음 날 12:00까지(인터뷰 7번 '다음 날 오전', 12:00은 팀 기본값). 예약 발송은 하지 않음

### 문안 구성
1. 호칭과 발신자: "{이름} {직함}님, 안녕하세요. 이음러닝 마케팅본부장 한서윤입니다." 직함이 없으면 "담당자님, 안녕하세요."로 씁니다.
2. 참석 감사와 연락 이유: 행사 날짜와 행사명을 넣어 감사 인사를 하고, "발표 자료를 공유드리고자 메일 드립니다"로 연락하는 이유를 밝힙니다.
3. 발표 자료 링크
4. 설문 문단: 받는 사람에 따라 둘 중 하나가 들어갑니다.
   - 설문 요청: 3분 만족도 설문 요청, 설문 링크, "이미 응답하셨다면 넘어가셔도 됩니다."
   - 설문 응답 감사: 현장에서 이메일을 적고 응답한 사람에게 "아울러, 현장에서 만족도 설문에 참여해 주셔서 감사합니다"로 시작하는 감사 인사(요청 없음)
5. 회신 안내, 맺음 인사("감사합니다."), "이음러닝 한서윤 드림"
6. 서명(`signature.txt`): 구분선, 회사와 부서("이음러닝 | 마케팅본부"), 이름과 직함("한서윤 본부장"), 전화, 이메일

### 제목의 근거
`[이음러닝] {행사명} 참석에 감사드립니다`
- 05 과거 발송 문안의 감사 메일 제목 "[이음러닝] 참석해 주셔서 감사합니다"의 머리말과 감사 표현을 그대로 이어받았습니다.
- 05 과거 발송 문안의 참가 안내 메일 제목 "[이음러닝] CEO 인사이트 특강 참가 안내"처럼 행사명을 넣었습니다. 여러 행사에 참석한 사람(3분기 18명)이 받은 메일함에서 어느 행사의 메일인지 구분할 수 있게 하기 위해서입니다.

### 05 과거 발송 문안과의 차이
05 과거 발송 문안의 감사 메일(전원 동일 문구, 행사명과 링크만 교체)의 흐름(감사 → 발표 자료 → 3분 설문 → 회신 안내)은 그대로 두고, 아래를 바꿨습니다.
- 제목에 행사명을 넣었습니다(위 "제목의 근거").
- "안녕하세요, 이음러닝입니다" 대신 직함으로 부르고(모르면 "담당자님"), 발신자를 마케팅본부장 한서윤으로 밝힙니다(06 글쓰기 기준 1(말투), 인터뷰 9번). 끝에 서명을 붙입니다.
- 본문에 행사 날짜와 행사명을 넣고, 첫 문단에서 연락하는 이유(발표 자료 공유)를 밝힙니다(06 글쓰기 기준 1(말투)).
- 요청은 설문 하나만 넣습니다(06 글쓰기 기준 1(말투)). 현장에서 이미 응답한 사람에게는 요청 대신 응답 감사 문단을 넣어 요청이 없습니다(인터뷰 7번).
- 설문 요청 문단에 "이미 응답하셨다면 넘어가셔도 됩니다."를 넣었습니다(인터뷰 7번).
- 회신 안내 "궁금하신 점은 이 메일에 회신해 주세요"를 합니다체인 "추가로 궁금하신 사항이 있으시면 이 메일에 회신해 주시기 바랍니다"로 바꿨습니다(06 글쓰기 기준 1(말투)).

### 글쓰기 기준 자동 검사 (06 글쓰기 기준 3)
초안마다 아래 항목을 검사하고, 걸리면 실행이 끝날 때 `[경고] 행사/이메일: 사유`를 출력합니다.

- 감사 메일은 250통입니다(E01 80, E02 45, E03 20, E04 38, E05 42, E06 25). 두 행사 이상에 참석한 18명은 행사마다 한 통씩 받습니다.

- 실제로는 E01·E02·E04·E06의 감사 메일이 행사 3~5일 뒤에 나갔고, E03·E05는 보내지 못했습니다(events.csv). 이 스크립트로 만들면 모든 행사의 감사 메일을 다음 날 12:00 발송 기한으로 준비할 수 있습니다.

## 승인·예약·발송 (실제 발송 없음)

초안을 DB에 넣은 뒤(`build_thanks.py` → `load.py`, 초안은 `mail_drafts`의 `mail_type='thanks'`) 본부장이 API로 행사 단위 승인을 합니다. **실제 메일은 보내지 않고 승인 상태만 `mail_approvals`에 기록합니다.** 주소는 [backend/README.md](../backend/README.md)의 API 표를 봐 주세요.

1. `GET /thanks`로 행사별 상태를 보고, `GET /thanks/{event_id}`로 받는 사람별 제목·본문을 확인합니다.
2. `POST /thanks/{event_id}/approve`로 승인합니다.
   - `mode: "now"`: 지금 발송으로 기록 (`sent`, 발송 시각 = 지금)
   - `mode: "scheduled"` + `scheduledAt: "YYYY-MM-DD HH:MM"`: 예약 (`scheduled`)
   - `excludedEmails`: 이번에 보내지 않을 사람. `excluded`로 기록
   - 예약 시각이 지금보다 과거면 거절(400), 발송 기한(`send_by`)보다 늦으면 저장하고 `warnings`로 알려 줍니다.
   - 발송 예정 상태에서 다시 승인하면 새 승인으로 덮어씁니다(예약 시각·제외 대상 변경). 이미 발송된 행사는 다시 승인할 수 없습니다(409).
   - 승인할 때 초안마다 그 시점의 `body_hash`(제목+본문)를 같이 저장합니다.
3. `POST /thanks/{event_id}/cancel`: 예약 시각이 아직 안 왔을 때만 그 행사 승인 기록을 지워 검토 상태로 되돌립니다. 발송된 메일은 취소할 수 없습니다(409).

행사 상태: `draft`(초안 없음) → `review`(승인 전) → `scheduled`(예약 시각 전) → `sent`(지금 발송했거나 예약 시각이 지남). 시간은 한국 시간(Asia/Seoul) 기준입니다.

**승인 무효**: 승인 뒤에 초안을 다시 만들어(`build_thanks.py` → `load.py`, 또는 화면에서 문안 저장) 제목이나 본문이 바뀐 사람이 있으면 그 사람의 `approvalInvalid`가 `true`가 되고, 발송 전이면 행사는 `review`로 돌아가 다시 승인해야 합니다. 이미 발송된 행사는 되돌릴 수 없으므로 `sent`로 남고 받는 사람별 `approvalInvalid`로만 표시됩니다.

## 화면에서 문안·링크 고치기

감사 메일 화면(`/follow-up/thank-you`)의 "05 감사 메일 문안 → 문안 수정"과 "04 자료·설문 링크"에서 **행사별로** 제목, 본문, 설문 요청 문단, 발표 자료 링크, 설문 링크를 고칠 수 있습니다. API는 [backend/README.md](../backend/README.md)의 `/thanks/{event_id}/template` 주소입니다.

- 저장하면 DB `thanks_settings`에 그 행사 1행으로 저장(다시 저장하면 덮어씀)하고, 그 행사 초안 전체를 `build_thanks.py`의 같은 함수(`render_with_settings`)로 다시 만듭니다. 받는 사람별 이름·직함·설문 포함 여부는 그대로입니다.
- 고정(고칠 수 없음): 현장 응답자에게 들어가는 설문 응답 감사 문단, 서명(`signature.txt`), 보내는 사람·발송 기한(`config.json`)
- 쓸 수 있는 자리 표시 (template.txt와 같은 모양)

| 칸 | 자리 표시 |
|---|---|
| 제목 | `{이름}` `{직함}` `{행사명}` `{M월 D일}` |
| 본문 (서명 앞까지) | 제목 것 + `{발표 자료 링크}` `{설문 문단}` |
| 설문 요청 문단 | 제목 것 + `{발표 자료 링크}` `{설문 링크}` |

- `{설문 링크}`는 설문 요청 문단에서만 씁니다(현장 응답자 메일에 설문 링크가 들어가지 않게). 본문에는 `{설문 문단}`이 꼭 한 번 있어야 합니다.
- 거절(400): 빈 칸, 그 칸에서 쓸 수 없는 자리 표시, `{설문 문단}`이 없거나 두 번 이상, `http://`·`https://`가 아니거나 공백·`@`가 들어간 링크(`config.json`과 같은 개인정보 규칙)
- 발송 완료된 행사는 고칠 수 없습니다(409). 발송 예정 행사에서 저장하면 제목·본문이 바뀌므로 `body_hash`가 달라져 **승인이 자동으로 무효**가 되고 행사는 `review`로 돌아갑니다. 다시 승인해야 합니다.
- 저장 결과의 `warnings`는 위 글쓰기 기준 자동 검사 결과입니다(저장은 됨).
- "기본 문안으로 되돌리기"(`/template/reset`)는 `thanks_settings` 행을 지우고 template.txt + config.json 기본값으로 다시 만듭니다.
- `load.py`는 `thanks_settings`를 비우지 않습니다. `build_thanks.py` → `load.py`를 다시 돌려도 이 표에 행이 있는 행사는 고친 문안·링크로 다시 만들어 넣습니다(CSV 원문은 쓰지 않음). 행이 없는 행사는 CSV 그대로입니다.

## 남은 일·가정

- `config.json`의 링크는 모두 시연용 가짜 값입니다(`https://example.com/slides/E04` 형식). 실제 링크로 바꿔야 합니다.
- **`signature.txt`의 연락처(전화 02-0000-0000, 휴대전화 010-0000-0000, 이메일 sy.han@ieumlearning.example)는 모두 시연용 가짜 값입니다.** 실제로 보내기 전에 바꿔야 합니다. 메일 본문에는 "예시" 표시를 넣지 않았으므로, 시연용 가짜 값이라는 사실은 이 문서에만 적혀 있습니다.
