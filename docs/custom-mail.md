# 맞춤 메일 초안 + 영업 전달 패키지 (backend/custom_mail)

담당: 소민 · 출석자마다 나갈 맞춤 메일 초안과, 영업으로 넘길 사람의 근거 묶음을 만듭니다.

## 하는 일

출석자마다 나갈 맞춤 메일 초안과, 영업으로 넘길 사람의 근거 묶음을 만듭니다.
**모든 메일은 초안이에요.** 본부장 승인 전에는 발송하지 않습니다 (06 글쓰기 기준).

## 입력·출력

- `out/custom_mails.csv`: 행사·사람별 메일 초안 (제목, 본문, 고른 글과 이유, 승인 방식, 글쓰기 기준 경고)
- `out/sales_handoff.csv`: 영업 담당자용 근거. 회사 산업군(KSIC, 내부용 — 메일 본문엔 안 씀), 어느 행사에 왔는지, 무엇을 물었는지, 설문 응답, 지난 연락 기록, 보낸 글, 연락 기한 (07 영업 전달 사례에서 요청한 정보)

## 규칙과 근거

### 메일을 만드는 방식
**틀이 사실과 약속을, AI가 연결 문장을** 맡습니다. 기준 메일은 소민이 직접 쓴 고진혁 전무 메일을 다듬은 것입니다.
- **틀 (바뀌지 않음):** 호칭(직함), 행사명, 재방문 문장, 담당자 연락 날짜(발송 후 영업일 3일), 글 제목·링크, 서명(마케팅본부장 한서윤)
- **AI가 쓰는 문장 (`mail_writer.py`):**
  1. 질문을 그대로 인용하지 않고 자연스럽게 받는 문장
  2. 영업: 왜 회사 상황을 여쭤야 하는지 / 글 안내: 이 글이 질문에 어떻게 도움 되는지 / 담당자: 확인 후 답변
  3. 영업만: 한 줄로 답할 수 있는 선택 질문 ("혹시 ~ 있으시면 회신으로 한 줄만 남겨 주십시오. 그 내용을 기준으로 준비해서 연락드리겠습니다") — 답장이 없어도 날짜에 맞춰 연락함
- **AI 재료는 질문·직함·글 제목/주제뿐**입니다. 숫자, 비율, 다른 회사 사례, 회사 이름, 효과 주장, 따옴표 인용, 느낌표, 금지 표현이 들어간 AI 문장은 자동으로 버리고 틀 문장으로 바꿉니다. 키가 없으면 전부 틀 문장입니다 (`sentence_source` 열에 표시).
- 제목에 질문 주제를 넣습니다: "[이음러닝] ○○ 특강에 남겨 주신 ‘사내 자료 사용 기준’ 관련"
- 같은 행사에 같은 회사 사람이 여럿이면 `note`에 표시해서 본부장이 문장 겹침을 확인하게 합니다.
- **글 고르기:** 질문마다 맞는 글을 `question_map.json`의 `article`에 짝지어 두었습니다 (검수 대상). 처음 보는 질문은 AI가 36편 중에서 고르고, 맞는 글이 없으면 "없음"으로 둡니다. **메일 보내는 날 아직 발행되지 않은 글은 쓰지 않고**, 같은 주제의 다른 글로 대신하지도 않습니다. 글 안내인데 맞는 글이 없으면 담당자 갈래로 바꿉니다.
- **글쓰기 기준 자동 검사:** 합니다체가 아닌 문장, 금지 표현, 느낌표 두 개 이상, 이모지, 잘못된 제품명을 찾으면 `lint` 열에 경고를 남깁니다.

### 담당자 이름 · 설문에 남긴 말 · 다음에 쓸 글 (11/25 밤)
- **담당자 이름:** `staff_directory.csv`(⚠️ **시연용 가짜 값**)에서 담당자를 배정합니다. 영업은 회사 산업군(KSIC 대분류)이 맞는 담당자, 담당자 확인 질문은 교육컨설팅팀. 같은 회사는 항상 같은 사람에게 배정됩니다. 메일에는 "영업1팀 김도현 매니저가 7월 17일까지 연락드리겠습니다"처럼 들어가고, 영업 전달 패키지에도 담당자·이메일이 붙습니다. 실제 운영 때는 이 표만 바꾸면 됩니다.
- **설문에 남긴 말:** 설문에서 '도움이 된 내용'을 적은 사람에게 "설문에서 ‘다른 회사의 도입 사례’가 도움이 되었다고 남겨 주셔서 감사합니다"를 한 문장 넣습니다 (본인이 직접 쓴 말만 사용).
- **다음에 쓸 글 목록 `out/content_gaps.csv`:** 질문은 있었는데 메일 시점에 맞는 글이 없었던 주제를 몇 명이(임원 몇 명) 언제부터 물었는지 정리합니다. 글이 행사 뒤에 나온 경우는 "글은 있지만 행사 뒤에 발행됨"으로 표시됩니다. 예: '사내 자료 사용 기준'은 7월부터 11명(임원 7명)이 물었지만 맞는 글은 9월 19일에 발행됨.

### 질문에 정보를 주는 메일 (11/26 새벽)
- **답변 근거 (11/26):** 답변마다 `basis`(근거: 제목·링크·무엇을 뒷받침하는지)와 `basis_level`(strong / partial / none)을 붙였습니다. **근거가 없는 답변은 승인 여부와 상관없이 메일에 넣지 않습니다.** 근거는 정부·공공기관 자료(국가정보원 AI 보안 가이드북, 개인정보보호위원회 안내서, 개인정보 보호법 제18조), 학술 연구(Kirkpatrick 4단계, Cepeda 2006 분산 학습 메타분석, Schmidt & Hunter 1998), 널리 쓰이는 지침(Andrew Ng AI Transformation Playbook, ICAEW RPA 가이드)입니다. 지금은 strong 12 · partial 3 · none 4. 실행 로그의 '근거가 없어 메일에 넣지 않는 답변'은 3개로 나옵니다. none 4개 중 '코딩 테스트 AI 허용'은 민감 질문이라 답변 문장 자체가 비어 있어 먼저 제외되기 때문입니다. 검수표는 `out/answer_bank_review.csv`.
- **답변 재료집 `answer_bank.json`:** 질문 유형마다 사람이 쓰고 본부장이 승인한 짧은 답변(2~3문장). AI는 이 문장을 바꾸지 않고 그대로 넣습니다. `status`가 `approved`인 것만 메일에 들어가고, `--include-drafts`를 주면 검수 전(`draft`) 답변도 미리 보기로 넣습니다 (`note`에 "검수 전 답변 포함 — 승인 필요" 표시). ⚠️ 지금 문장은 **Claude가 쓴 예시 초안**이고, 실제 운영에선 이음러닝 담당자가 씁니다. 민감 질문(코딩 테스트 AI 허용)은 인터뷰 6번에 따라 첫 메일에 답을 넣지 않습니다.
- **메일 구조 3덩어리:** ① 인사 ② 참석 감사(재방문·설문) + 질문 받기 + 답변 재료 ③ 담당자 약속 + 선택 질문 (+ 글, 맺음말). 같은 말이 두 번 나오지 않게 했습니다.
- **숫자 안전장치:** 질문에 원래 있던 숫자("1년")는 허용하고, 새로 생긴 숫자만 지어낸 것으로 봅니다.
- **질문 없는 영업 메일:** 왜 연락하는지 그 사람이 남긴 사실로 한 문장 넣습니다 (설문 연락 요청 / 도입 검토 / 행사장 대화).

### 수신 미동의자의 영업 건 (11/26 새벽 3)
- 인터뷰 기준상 미동의자에게는 "감사 인사, 발표 자료, 설문, **본인 질문에 대한 답**까지만" 보낼 수 있습니다. 질문에 답하는 것과 영업 담당자가 먼저 연락하는 것은 다르다고 보고, **미동의자의 영업 건은 질문에 답만 하고, 연락은 고객이 회신으로 원할 때만** 하도록 했습니다 ("회사 상황에 맞춰 더 자세히 안내받기를 원하시면 이 메일로 회신해 주십시오").
- 예외: 설문에서 **직접 담당자 연락을 요청한** 사람은 미동의자라도 먼저 연락합니다 (본인이 요청한 것).
- 영업 전달 패키지에는 그대로 넘기되 `contact_mode`를 "회신 오면 연락 (수신 미동의 — 먼저 연락하지 말 것)"으로 표시하고, 연락 기한(`contact_due`, `promise_due`)은 비워 둡니다. 3분기: 먼저 연락 85 / 회신 오면 연락 26.
- ⚠️ 이 해석은 고객사 확인이 필요합니다 (영리 목적 광고성 정보 전송의 사전 동의 문제와도 관련).

### 여러 행사에 온 사람 (11/26 새벽 4)
- 앞 행사에서 이미 영업 담당자를 안내한 사람이 다음 행사에 또 오면, 새로 "담당자가 연락드리겠습니다"를 약속하지 않고 **"앞서 안내드린 영업1팀 김도현 매니저가 이번 질문도 이어서 ○월 ○일까지 말씀드리겠습니다"**로 씁니다. 실제 통화가 됐는지는 시스템이 모르므로 '안내드린'까지만 씁니다.
- 영업 전달 패키지의 `sales_status`: "신규" 또는 "이미 진행 중 — ○○에서 담당자 안내함, 새 질문 추가". 같은 회사는 항상 같은 담당자라 이어서 맡습니다. 3분기: 4건.
- 질문 없는 영업 메일의 제목은 그 사람이 실제로 한 일만 씁니다: 설문 연락 요청 → "설문에서 요청해 주신 담당자 연락 관련", 도입 검토 응답 → "설문에서 답해 주신 AI 교육 도입 검토 관련", 현장 기록 → "○○ 이후 연락드립니다" (남긴 게 없는데 '남겨 주신'이라고 쓰지 않음).
- 질문도 남기고 설문에서 연락도 요청한 사람은 "설문에서 담당자 연락도 요청해 주셔서, ○○가 …까지 연락드리겠습니다"로 연락 이유를 밝힙니다 (수신 미동의자도 본인 요청이라 먼저 연락 가능).

### 사실 확인 자동 검사 (`fact_check`)
메일을 만들 때마다 사람이 읽기 전에 자동으로 확인합니다. 걸리면 `lint` 칸에 이유가 적히고, 실행 결과의 "글쓰기 기준·사실 확인 경고"가 0이 아닙니다.
- 사실: 남긴 게 없는데 '남겨 주신' / 질문 없는데 '신청하시며' / 설문 기록 없는데 '설문에서'
- 동의: 미동의자에게 이유 없이 먼저 연락 / 회신 대기자에게 날짜 약속 / 미동의자에게 홍보 문구
- 약속: 배정 담당자 이름·연락 날짜가 본문과 일치 / 고른 글 제목이 본문에 있음
- 문장: 감사 인사 중복
